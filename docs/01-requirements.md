# 01 需求与成功标准

## 用户、目标与范围

用户是内容团队的排期操作人员。输入素材 ID、带时区的发布时间要求及已有排期；系统读取元数据、审核规则并形成可确认草稿。审核结果必须可追溯到工具返回，保存状态必须对应数据库实际状态。

本项目每次 CLI 请求处理一个素材，多素材通过多次调用共享 SQLite 数据库。仅处理合成元数据，不读取真实视频、不执行发布。提供主素材、归档补查、规则审核、时段查询及草稿保存能力；归档补查共用素材读取工具。

## 业务不变量

1. 模型不能修改原请求。硬性时段被占用时，替代时段需要用户确认；待确认草稿的 effective_slot 必须为空。
2. 素材未读、元数据不足、审核未通过时，不得保存排期。
3. 所选时段必须出现在查询结果中，保存时再次检查可用性。
4. 相同需求重复执行只保留一个草稿；占用变化时更新原草稿，避免沿用失效建议。
5. 保存失败不能称为成功；成功结果不能因后续失败而消失。
6. 没有发布动作；所有最终结果 published=false。
7. 模型请求次数有上限，达到上限明确返回 incomplete。

## 验收映射

| 题目验收点 | 输入案例 | 成功标准 |
| --- | --- | --- |
| 正常排期 | normal | approved；原时段保存；数据库 1 份草稿 |
| 素材信息缺失 | missing / supplement | 补查归档；不足则列出 rights_status，补齐则重新审核 |
| 规则风险 | risk / manual_review | 无授权素材阻断；未验证宣传表述请求人工复核 |
| 时段冲突 | conflict / confirmed | 18:00 占用时建议 19:00，未经确认 effective_slot=null；显式确认后可保存确认草稿 |
| 重复提交 | normal_repeat / conflict_repeat / conflict_moved | 重复为 existing；更换占用后为 updated，草稿 ID 和数据库计数不变 |
| 保存失败 | save_failure | failed，无新增数据库行，无伪造 draft_id |

额外检查：查询暂时失败、保存瞬间竞争、无可用时段、跨请求冲突、并发唯一性、模型越权参数、模型失败和执行上限。

## 技术约束和取舍

优先交付 CLI 和可复制的测试。语言为 Python 3.11+，本地验证 3.12.4；业务工具均为本地函数，持久化使用标准库 sqlite3。真实模型采用 DeepSeek HTTP 接口，避免引入不必要的框架依赖。离线 Mock 仅用于业务流程验证。
