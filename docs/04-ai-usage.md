# 04 AI 使用、个人贡献与验证

## 披露原则

本项目由候选人与 Codex 协作完成。下述内容按本次会话实际发生的工作记录，不能将 AI 实现的代码和文档表述为候选人独立编写。模型运行证据与离线模拟分别标注。

## 使用范围

| 内容 | 本次实际贡献 |
| --- | --- |
| 题目与约束输入 | 用户提供四道完整题面、统一交付规范和 GitHub 仓库 |
| 方案比较与选题 | Codex 分析选题；用户确认选择第一题 |
| 目标与过程记录 | 用户要求设立目标并记录全过程；Codex 执行记录 |
| 业务设计、程序、测试、文档 | 由 Codex 编写、审查、修改并执行验证 |
| 真实模型接入 | 用户指定可使用 CC Switch 中正在供本地 Claude Code 使用的 DeepSeek 配置；Codex 在本地进程中使用，不复制或提交凭证 |
| 个人手工代码修改 | 截至本次交付，未观察到用户手工修改代码；不作虚构声明 |
| 验收与修正 | Codex 实际运行自动化测试、离线案例和 DeepSeek 案例，记录结果并修复发现的问题 |
| 第二轮深化 | 用户要求从第一性原理完善并做对抗性审查；Codex 推导不变量、复现攻击、修复代码并再次验证 |

工程辅助工具为 Codex；业务 Agent 的真实决策模型为 deepseek-flash。它们承担不同职责：前者协助写项目，后者在项目运行过程中根据实际工具反馈选择行动。

## 重要修正与验证

1. 最初发现系统 Codex CLI 与本地配置/网络不兼容，尝试未成功；没有将失败尝试伪装成模型验证。获得用户指定后改为直接调用 DeepSeek API；最终代码移除了未成功验证的 Codex CLI 适配器。
2. 审查重复提交语义时发现：工具端占用改变后，直接返回旧草稿会产生过期建议。修改为重新校验后原位更新同一草稿，并增加换占用、同请求、同数据库测试与真实运行。
3. 增加成功结果保留：后续一次失败保存尝试不覆盖已存在的成功成果；Trace 仍保留失败，最终输出保留真实草稿 ID。
4. 硬性发布要求与确认状态由程序强制校验；用恶意模型动作测试不能通过新增参数伪造用户确认。
5. 完整真实模型评估发现：补查失败后模型可能直接结束，不再调用 check_rules。原实现将此误归为工具失败；修正为根据已读取的缺失字段返回 needs_information，同时保留 review_status=not_checked，不伪造已审核。失败 Trace 与修正前汇总保留在 examples/regressions/，增加对应回归测试后重新验证。

验证命令、测试结果与实际模型 Trace 见 [03-evaluation.md](03-evaluation.md)。没有凭空填写测试通过率或预设真实决策日志。

第二轮发现初版“保留成功结果”处理过于粗糙：旧成功可能掩盖新失败。现改为最新 save_status 与 persisted_draft 分离；同时修复归档覆盖风险、旧证据失效、未知风险和失败请求身份绑定。九个攻击的原始失败与修复结果均保留。对抗脚本与有限动作枚举属于测试替身证据，不冒充真实模型评估。详见 07-first-principles.md 和 08-adversarial-review.md。

本轮真实模型还暴露一次动作协议校验失败；保留失败后加入同预算内的校验错误反馈，由模型选择修正或结束。程序不执行无效动作，也不放宽确认与风险边界。身份已拒绝的请求也不会触发其他草稿的状态变更。

## 数据与凭证

所有素材、风险规则、排期、请求和故障均为合成。真实模型运行的密钥仅由本地未提交的凭证桥接进程载入；仓库本身只读取环境变量，不依赖个人配置路径。未提交密钥、Claude 配置、CC Switch 数据库、真实素材或模型内部思维过程。

## 候选人复核状态

本记录不能代替候选人对实现的理解。截至 AI 交付时，候选人尚未在本会话中完成逐项代码讲解或亲自运行复核。后续个人修改、运行与学习收获应按事实追加到过程记录，再决定最终提交版本。
