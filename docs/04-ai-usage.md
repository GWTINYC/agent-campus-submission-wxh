# 04 AI 使用、个人贡献与验证

## 协作方式

本项目使用 Codex 辅助完成方案设计、代码、测试和文档。用户提供题目与业务约束，确认选题和模型接入方式，并参与文档修订。离线流程验证与真实模型评估分别记录。

## 使用范围

| 内容 | 本次实际贡献 |
| --- | --- |
| 题目与约束输入 | 用户提供四道完整题面、统一交付规范和 GitHub 仓库 |
| 方案比较与选题 | Codex 分析选题；用户确认选择第一题 |
| 目标与过程记录 | 用户要求设立目标并记录全过程；Codex 执行记录 |
| 业务设计、程序、测试、文档 | 由 Codex 编写、审查、修改并执行验证 |
| 真实模型接入 | 用户指定本地 CC Switch 中的 DeepSeek 配置；Codex 完成接口适配和实际运行 |
| 文档修订 | 用户修改并上传复盘，Codex 按用户要求统一其余文档的表达 |
| 验收与修正 | Codex 实际运行自动化测试、离线案例和 DeepSeek 案例，记录结果并修复发现的问题 |
| 第二轮深化 | 用户要求从第一性原理完善并做对抗性审查；Codex 推导不变量、复现攻击、修复代码并再次验证 |

工程辅助工具为 Codex；业务 Agent 的真实决策模型为 deepseek-flash。它们承担不同职责：前者协助写项目，后者在项目运行过程中根据实际工具反馈选择行动。

## 重要修正与验证

1. 环境检查发现系统 Codex CLI 与本地配置、网络不兼容，随后采用用户指定的 DeepSeek API 完成真实接入。
2. 审查重复提交语义时发现：工具端占用改变后，直接返回旧草稿会产生过期建议。修改为重新校验后原位更新同一草稿，并增加换占用、同请求、同数据库测试与真实运行。
3. 分离最新保存尝试与持久化记录：失败状态和已有草稿分别展示，便于核对修改结果。
4. 硬性发布要求与确认状态由程序强制校验；用恶意模型动作测试不能通过新增参数伪造用户确认。
5. 真实模型评估发现：补查失败后模型可能直接结束。修正该路径的状态归类，根据已读取的缺失字段返回 needs_information，审核状态保持 review_status=not_checked，并增加对应回归测试。过程记录见 examples/regressions/。

验证命令、测试结果与实际模型 Trace 见 [03-evaluation.md](03-evaluation.md)。

第二轮按第一性原理重新推导状态和证据约束，修复归档覆盖风险、旧证据失效、未知风险和失败请求身份绑定。九个攻击提供修复前后对照；对抗脚本和动作枚举验证业务约束，DeepSeek 运行验证模型根据工具反馈调整行动。详见 [第一性原理题解](07-first-principles.md) 和 [对抗审查报告](08-adversarial-review.md)。

真实模型运行还发现一次动作协议校验失败，随后加入同预算内的校验错误反馈，由模型选择修正或结束。动作校验、确认权限和请求身份检查共同保护草稿状态。

## 数据与凭证

素材、风险规则、排期、请求和故障均采用合成数据。模型密钥由本地进程载入，项目通过环境变量读取配置，仓库提供 .env.example。运行记录包含动作、参数、工具返回、简短决策依据及模型用量。

## 验证材料

自动化测试、实际模型输出、失败修正和开发时间分别记录于 examples/、03-evaluation.md 和 06-process-log.md，可结合源码与 Trace 复现关键路径。
