# 05 复盘

以下由 AI 根据实际开发与验证过程整理，描述项目层面的发现；不代替候选人自己的学习陈述。

## 最难的问题

最难的是同时满足“同请求不产生第二份草稿”和“工具结果改变后不能复用过期建议”。只用幂等键直接返回旧结果，18:00/19:00 占用互换后仍可能返回已冲突的建议。

最终做法是区分需求身份和最新排期方案：需求指纹稳定、草稿 ID 稳定；每次重新读取、审核和查询，再在事务中更新同一份草稿。测试同时检查建议时段、原始要求、草稿 ID 和数据库行数；真实模型运行也覆盖占用替换后的重复提交。

## 实际学习与设计收获

- 模型擅长根据观察选择下一步，但确认边界和唯一性必须由业务代码保证。
- 待确认建议与已确认草稿时段需要分别存储，才能避免未经授权的改期和错误占位。
- 任务状态与保存状态应分开：达到步数上限仍可能已有草稿；工具失败也不能抹掉已成功的结果。
- 一条能运行的 happy path 不足以证明 Agent；需改变工具返回、注入失败，再核对真实下一步动作。
- 实际环境检查比假设接口可用更可靠。本次 Codex CLI 尝试失败，改用用户明确指定的 DeepSeek 配置后完成真实接入。
