## 已复现的问题

| 攻击 | 旧实现实际问题 | 修复 |
| --- | --- | --- |
| 归档洗白风险 | 主资料未授权被归档 licensed 覆盖，随后能保存 | 归档只补缺失字段；矛盾进入人工复核；阻断风险保留 |
| 未知风险标签 | 未列入已知规则就按无风险通过 | 未知标签转人工复核 |
| 审核后素材变更 | 使用旧的 approved 保存已变为未授权的素材 | 保存前比较资料与规则摘要；失效后要求重新读取和审核 |
| 旧成功掩盖新失败 | 已有草稿时，后续失败仍报告 saved/completed | 最新尝试与持久化记录分别呈现，失败不能被历史成功覆盖 |
| 新风险未撤销旧占位 | 重新审核 blocked，但旧确认草稿继续占位 | 撤销旧证明，标记 invalidated，释放 effective_slot，保留历史 |
| 失败请求 ID 重绑定 | 失败运行未登记 ID，随后同 ID 可换素材 | 首次模型调用前在事务中绑定需求指纹 |
| 风险字段格式异常 | risk_tags=null 导致运行异常 | 类型验证，返回信息不足，不解释为无风险 |
| 伪确认值被忽略 | confirmed_slot=false 被静默视为未填写 | 非 null 的确认值必须是合法非空时间字符串 |
| 硬性时间精度丢失 | 18:00:00.5 被截断为 18:00，错误当作满足原要求 | 保留完整时间精度，不能把近似时间变为已授权时间 |

九个用例是针对已发现薄弱点的定向攻击；旧版九例均未满足安全断言，不代表旧版所有正常案例失败。攻击中需要旧草稿的场景会先断言初始保存成功，避免“所有保存都失败”产生伪安全结果。

## 扩展审查

- 用三种素材状态分别枚举长度为四的六种业务动作组合，加 finish，共 3,888 条序列。检查风险/缺失素材不能产生确认草稿、硬性时间不能被改变、无重复草稿、有效审核版本对应当前资料。
- 构造实际本地 HTTP 302 重定向，验证携带测试令牌的请求不会转发给第二个服务；令牌为虚构测试值。
- 检查响应体过大、截断响应、动作参数夹带确认信息、假发布动作、审核规则变化、保存后时段变化和等价时区重复请求。
- 正常验收与数据库成功读回同时运行，防止通过“一律拒绝”规避攻击。

## 实现过程中的回归

请求 ID 改为入口登记后，旧保存逻辑仍执行普通 INSERT，造成身份记录重复，正常保存回归失败。正常用例发现了这一问题；修正为已有绑定校验通过后 INSERT OR IGNORE，再同时复测正常与攻击路径。没有以安全用例通过代替正常业务回归。

本轮第一遍真实模型评估还出现补查动作不符合协议而中止的情况。保留 [失败 Trace](../examples/regressions/supplement-invalid-action-before-repair.json) 与 [该轮汇总](../examples/regressions/evaluation-before-action-repair.json)。原始日志仅表明动作校验失败，未保留更细的字段错误，因此不臆测具体错误字段。新增有界的 action_validation 观察反馈，模型可修正后再提出动作；无效动作始终不执行，且消耗总步数预算。对合法修正和反复提出发布动作分别测试。

## 结论边界

本地合成环境支持可重复的状态检查，真实 DeepSeek 运行用于观察模型如何根据工具反馈调整。有限枚举不是形式化证明，素材提示注入样例也不能证明对任意提示攻击免疫。仍不包含真实用户身份认证、远程资料签名、任意时间区间冲突或跨服务事务；这些限制保留在评估文档中。
